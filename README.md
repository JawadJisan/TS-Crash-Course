## TypeScript Concepts

### Basic annotations and inference

Use an annotation when the type is not obvious or when you want to document a contract. TypeScript infers the type when it can.

```ts
const country: string = 'Bangladesh';
const population = 170_000_000; // inferred as number

// population = 'many'; // Error: string is not assignable to number
```

See `assets/ts/types.ts` and `assets/ts/diffrentTypes.ts`.

### Arrays and object types

An array annotation constrains every item. Object types define the required keys and values.

```ts
const scores: number[] = [10, 20, 30];

type User = {
  id: number;
  name: string;
};

const user: User = { id: 1, name: 'Amina' };
```

See `assets/ts/arr-object.ts`.

### Functions and `void`

Annotate a function return when its public result matters. Use `void` for a function that performs an action without returning a value.

```ts
function divide(a: number, b: number): number {
  if (b === 0) throw new Error('Division by zero is not allowed');
  return a / b;
}

function logResult(value: number): void {
  console.log(value);
}
```

See `assets/ts/example.ts`.

### Type aliases and interfaces

Both `type` and `interface` can describe an object. Interfaces are often used for extendable object contracts; type aliases are flexible and can also represent unions and tuples.

```ts
interface DatabaseConfig {
  host: string;
  port: number;
}

type AppConfig = {
  appName: string;
  database: DatabaseConfig;
};
```

See `assets/ts/typeInterface.ts` and `assets/ts/interfaceTypes.ts`.

### Optional properties and `Omit`

Use `?` when a property may be absent. Use `Omit` to create an input type without properties generated by the application.

```ts
type User = {
  id: number;
  name: string;
  email?: string;
};

function createUser(input: Omit<User, 'id'>): User {
  return { id: Date.now(), ...input };
}
```

See `assets/ts/optional.ts` and `assets/ts/Omit.ts`.

### Literal types, unions, and narrowing

A literal union accepts only the listed values. When an input can be several object shapes, narrow it before accessing shape-specific properties.

```ts
type HttpMethod = 'GET' | 'POST' | 'DELETE';
type Circle = { radius: number };
type Rectangle = { width: number; height: number };

function area(shape: Circle | Rectangle): number {
  if ('radius' in shape) return Math.PI * shape.radius ** 2;
  return shape.width * shape.height;
}
```

See `assets/ts/Literal.ts` and `assets/ts/Union.ts`.

### Tuples and readonly tuples

Tuples preserve the type at each position. A `readonly` tuple prevents mutation after creation.

```ts
type DivisionResult = [quotient: number, remainder: number];
const result: DivisionResult = [3, 1];

const point: readonly [number, number] = [23.733, 90.4];
// point.push(10); // Error
```

See `assets/ts/TupleReturnFromFnc.ts` and `assets/ts/enum-Tuple.ts`.

### Enums

Enums create named runtime constants. String unions are often lighter for simple value sets, while enums can be useful when a named runtime object is needed.

```ts
enum Status {
  Draft = 'draft',
  Published = 'published',
}

const status: Status = Status.Draft;
```

See `assets/ts/Enum.ts`.

### `Map` and `Set`

`Set` stores unique values. `Map` stores typed key/value pairs and is useful for counters or lookups.

```ts
const tags = new Set<string>(['typescript', 'typescript']);
// tags contains one value

const orders = new Map<string, number>();
orders.set('Lemon juice', (orders.get('Lemon juice') ?? 0) + 1);
```

See `assets/ts/map-set.ts` and `assets/ts/map-example.ts`.

### Generics

Generics keep a relationship between an input type and an output type, without using `any`.

```ts
function firstItem<T>(items: T[]): T | undefined {
  return items[0];
}

const firstName = firstItem(['Amina', 'Karim']); // string | undefined
const firstNumber = firstItem([1, 2, 3]); // number | undefined
```

See `assets/ts/generic.ts`.

### Typed asynchronous APIs

Use a generic API helper to state the response shape at the call site. `response.json()` has no runtime validation, so production code should validate untrusted API data as well.

```ts
async function getJson<T>(url: string): Promise<T> {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`Request failed: ${response.status}`);
  return response.json() as Promise<T>;
}

type Product = { id: number; name: string; price: number };
const products = await getJson<Product[]>('/api/products');
```

See `assets/ts/generic-api.ts`.

### Classes, inheritance, and access modifiers

`public` is available everywhere, `protected` is available in a class and subclasses, and `readonly` can only be assigned during initialization.

```ts
class Account {
  constructor(
    public readonly id: number,
    public name: string,
    protected balance: number,
  ) {}

  deposit(amount: number): void {
    this.balance += amount;
  }
}

class StudentAccount extends Account {
  withdraw(amount: number): void {
    if (amount > 10_000) throw new Error('Withdrawal limit exceeded');
  }
}
```

See `assets/TSOOP/index.ts`.

### Modules

Use `export` to expose a value and `import` to consume it in another file.

```ts
// math.ts
export function add(a: number, b: number): number {
  return a + b;
}

// app.ts
import { add } from './math.ts';
console.log(add(4, 5));
```

See `Projects/TSWithNodeJS`.

### DOM element typing

When querying the DOM, provide the element type and handle the possibility that the element is absent.

```ts
const input = document.querySelector<HTMLInputElement>('#email');
const button = document.querySelector<HTMLButtonElement>('#send');

button?.addEventListener('click', (event) => {
  event.preventDefault();
  console.log(input?.value);
});
```

See `Projects/HtmlTS/script.ts`.

## Projects

### Newsletter Signup

`Projects/HtmlTS` is a browser form exercise that demonstrates typed DOM queries and event listeners. Compile `script.ts` into `script.js` before opening `index.html`.

### Node.js Math Module

`Projects/TSWithNodeJS` demonstrates a named export from `exp.ts` and an ESM import in `mathLib.ts`.

### Bundled Task Manager

`Projects/script-bundled` is the most complete application in the repository. It uses Rollup and is split by responsibility:

- `src/types.ts`: `Task` and `Filter` contracts.
- `src/data.ts`: initial task data.
- `src/ui.ts`: filter, summary, and task-list rendering helpers.
- `src/main.ts`: DOM access, application state, and event handlers.
- `src/seed.ts`: an earlier single-file version of the application retained for comparison.

It supports adding, completing, deleting, filtering, and counting tasks. The app is in-memory only, so a browser refresh resets its state.

### Vite TypeScript Demo

`Projects/vite-ts-demo` is the Vite starter project. It demonstrates TypeScript imports, asset imports, CSS, and a typed counter interaction.

## Run the Code

Install Node.js 20 or newer and TypeScript. The project folders that have a `package.json` also have lockfiles, so use `npm ci` for reproducible dependency installation.

### Run one lesson

Compile one independent lesson from the repository root:

```powershell
tsc.cmd assets/ts/map-set.ts --target esnext --outDir assets/js
node assets/js/map-set.js
```

Some lessons intentionally contain failing lines; see the next section before compiling every lesson at once.

### Run the newsletter project

```powershell
Set-Location Projects/HtmlTS
tsc.cmd script.ts --target esnext
Start-Process index.html
```

### Run the Node.js module example

```powershell
Set-Location Projects/TSWithNodeJS
tsc.cmd exp.ts mathLib.ts --target esnext --module nodenext --moduleResolution nodenext
node mathLib.js
```

### Run the Rollup task manager

```powershell
Set-Location Projects/script-bundled
npm.cmd ci
npm.cmd run build
npm.cmd run start
```

Open the local URL printed by `serve`.

### Run the Vite demo

```powershell
Set-Location Projects/vite-ts-demo
npm.cmd ci
npm.cmd run dev
```

Open the local URL printed by Vite.

## Teaching Examples That Intentionally Fail

The following active lines are there to show TypeScript's compiler feedback. Comment them out when you want a clean compile:

- `assets/ts/diffrentTypes.ts`: assigns a `string` to a `number`.
- `assets/ts/Literal.ts`: assigns `'yellow'` to a type limited to `'red' | 'green' | 'blue'`.
- `assets/ts/enum-Tuple.ts`: attempts to call `push` on a readonly tuple.

When compiling every lesson as one script collection, the two `divide` function declarations also share the global scope, and `generic-api.ts` needs to be treated as a module for its top-level `await`. Compile lessons independently, or add `export {}` to each file when converting them into one TypeScript project.

## Repository Notes

- `node_modules` and build output are ignored by Git. Package lockfiles are retained so dependencies can be restored exactly.
- The root `tsconfig.json` currently targets the standalone lesson output under `assets/js`. Each app project has its own TypeScript configuration.
- The task manager renders user-supplied task text with `innerHTML`; before deploying it, render text with DOM APIs or escape it to prevent HTML injection.
